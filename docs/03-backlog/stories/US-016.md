## Story
As an employee, I want the name field to accept only a real name of reasonable length, so that every booking carries a name others can recognise.

## Context and business rules
1. The name is free text typed at booking time. — REQ-006 `[W2 · Out of scope, explicitly confirmed]` "name is typed in at booking time"
2. A name of spaces only counts as empty; an empty name is refused. — REQ-035, DEC-018
3. A name has at most 50 characters. — REQ-035, DEC-018, ASM-018 (ASSUMPTION — not validated)
4. Plain-text display of names is tested where names are rendered — the Variant B tile (US-011); the confirmation does not show the name (US-005 rule 9).

## Acceptance criteria
```gherkin
Scenario: Name of spaces only
  When the employee types "   " as the name and books F1-07 for 2026-10-22
  Then the booking is refused and the name field asks for a name
  And F1-07 stays free and the counts do not change

Scenario: Empty name
  When the employee leaves the name empty and books F1-07 for 2026-10-22
  Then the booking is refused and the name field asks for a name

Scenario: Name of exactly 50 characters (boundary)
  When the employee books F1-07 for 2026-10-22 with a name of 50 characters
  Then the booking is confirmed

Scenario: Name of 51 characters (boundary + 1)
  When the employee books F1-08 for 2026-10-22 with a name of 51 characters
  Then the booking is refused with a message that a name has at most 50 characters
  And F1-08 stays free
```

## UI notes
Name field with an inline message for empty and too-long names.

## Out of scope for this story
Identity checks (OOS-002, DEC-012).
