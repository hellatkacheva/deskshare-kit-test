## Story
As the presenter of the demo, I want all bookings to be kept in this browser and the page to say so, so that the PoC runs without any backend and nobody mistakes the single-device demo for a shared system.

## Context and business rules
1. All booking data is stored only in this browser (`localStorage`); there is no server, database or third-party store. — NFR-005, DEC-001 `[W1 · Decisions]` "no shared backend/database for this phase", DEC-014
2. Data survives a page reload and a browser restart on the same device. — DEC-014, ASM-006 (ASSUMPTION — not validated)
3. A banner on every screen says: **"Demo — bookings are stored in this browser only."** — REQ-031, DEC-014
4. Another device or another browser does not see these bookings. — ASM-006 (ASSUMPTION — not validated)

## Acceptance criteria
```gherkin
Scenario: Banner on every screen
  Given the app is open
  When the employee opens any screen of the app
  Then the banner "Demo — bookings are stored in this browser only." is visible

Scenario: Data survives a reload (state effect)
  Given a booking for desk F1-07 on Thu 2026-10-22 under the name "Alex Morgan" exists in this browser
  When the page is reloaded
  Then the booking for F1-07 on 2026-10-22 under "Alex Morgan" is still there

Scenario: No network calls with booking data
  Given the app is loaded
  When the employee books, cancels or checks in
  Then no request carrying booking data is sent over the network

Scenario: Another browser does not see the data
  Given a booking exists in browser 1
  When the app is opened in browser 2
  Then the booking from browser 1 is not shown in browser 2
```

## UI notes
Banner text exactly as in rule 3; always visible, not dismissible (no decision allows hiding it).

## Out of scope for this story
Seed data (US-002). Any sync between devices (DEC-014).

## Dependencies
None — first story.
