## Story
As an employee, I want to add a short note to my booking, so that I can say what I need at the desk (for example "need a second monitor") without asking anyone.

## Context and business rules
1. A booking may have a note; the note is optional — a booking without a note is valid. — REQ-046 `[W4 · Workshop 4 — Booking note]` "Agreed: an optional note per booking"
2. The note is at most 50 characters, counted as Unicode code points after trimming leading and trailing spaces (the same counting as the name, US-016); a note of spaces only is no note. A longer note is refused at save with a message, not cut — the field has no length cap of its own. — REQ-047 "maximum 50 characters"; DEC-036
3. The note can be typed only when booking; there is no editing of a note (not in the source). — DEC-036
4. The booking confirmation shows the note, if any, as "Your note: …" under the date and desk; it still does not show the name. — REQ-048 "The note is shown on the booking confirmation"; refines REQ-036; DEC-036 (S4-11)
5. The desk dialog of a taken desk shows the note of that booking, if any, to anyone who opens it — with the names switch Off or On. The dialog shows the note, never the booker's name (names appear only on tiles in Variant B, US-011). — REQ-049 "and in the desk dialog"; ASM-019 (ASSUMPTION — not validated)
6. The note field says "Optional, up to 50 characters. Please do not include names."; there is no automatic check for names. — NFR-011 "No names of other people in it."; DEC-036 (hint text), ASM-020 (ASSUMPTION — not validated)
7. **Accepted cost:** a note that contains a name lets anyone who opens the desk dialog cancel or check in that booking by typing that name (RSK-012; the same misuse US-011 rule 8 accepts for Variant B, here also in Variant A). — RSK-012, DEC-012
8. The note is shown as plain text, never as markup. — DEC-036 (as US-011 rule 6)
9. The note is not shown on the desk tiles or in the floor counts; the "Tomorrow" screen shows counts only (US-013 rule 5). — DEC-036, NFR-002
10. **State effect:** the note is stored with its booking in this browser only (bookings saved before notes existed have no note and stay readable — storage version 1). It is removed with the booking on cancel and on auto-release, and deleted together with the name after the booking date (US-014 sweep); today's and future notes are kept. — REQ-050 "It is deleted together with the name after the booking date."; NFR-012 "keep it in the browser like everything else"; DEC-014, DEC-031, DEC-036, ASM-014
11. Next band, Must: built after the Core demo stories; not dropped without a recorded BA decision. — DEC-036

## UI notes
Booking form: an optional one-line "Note (optional)" field below the name, with the hint from rule 6; no `maxlength`. Confirmation: one line "Your note: …" only when there is a note. Desk dialog: one line "Note: …" only when there is a note. Text is set as plain text (`textContent`).

## Out of scope for this story
Editing a note; notes on tiles, counts or Tomorrow; an automatic name check; seeded notes (DEC-036).
