## 9. Kit observations (proposed)

- **K-22 — `blockdiff` hint `C1?` ignores scope words.** D1 got `C1?` (similarity 0.92) although "no" was removed. The script already computes `words.removed` / `added`; it could drop the `C1?` hint when they contain a scope word ("no", "not", "only", "must", "in scope", "out of scope").
- **K-23 — `blockdiff --out` does not create the folder.** The first run for CHG-003 failed with ENOENT on `docs/07-changes/CHG-003/changes.json`; `mkdir -p` by hand fixed it. Also: an unchanged child (`458755 v1 → v1`) is reported as `page_op: "page changed"` with 0 changes.

- **K-24 — snapshots must be saved as fetched, not assembled.** `v4/page.html` (CHG-002) and the first `v5/page.html` were built as the previous `page.html` + one text replacement after a spot check of the fetched html, because the MCP html body is large to pass through the model. That breaks golden rule 1 / README "the page exactly as fetched", and a replacement error would go unnoticed (the block diff then compares the assembled file with itself). Found by trace-auditor (CHG-003 B4). v5 was re-fetched and is byte-identical; v4 can no longer be checked (Confluence returns only the current version) and is marked in `v4/meta.json`. Proposal: `ingest-confluence` writes the MCP body to disk without passing through the model (e.g. a small script fed by the MCP response, or the REST API), records `sha256` of the body as fetched, and never derives a snapshot from an older one.
