There is no server and no API (DEC-014, NFR-005). The UI calls the functions of `app/public/js/storage.js`; they use the pure rules of `app/public/js/rules.js` and the time helpers of `app/public/js/time.js`. `now` is always passed in (office time `{ date: "YYYY-MM-DD", time: "HH:MM" }` from `clock.js`), so every rule is unit-testable with a fixed time (NFR-010).

## 1. Result shape

```js
{ ok: true, ...data }                         // success
{ ok: false, code: "DESK_TAKEN", message: "This desk is already taken — pick another desk." }
```
The UI shows `message` as plain text (`textContent`). Codes and texts: §4.

## 3. Storage operations (`storage.js`)

Every operation: **read** `STORAGE_KEY` → parse → **sweep** (release, then retention — data-model.md §4) → **check** → **write** if anything changed. One synchronous call — no `await` between read and write. Any storage exception → `STORAGE_OFF`; data stays as it was.

### 3.1 `open(now, { storage, host, search })` → `{ state, seeded, resetDone }`

| Step | Rule | Source |
|---|---|---|
| 1 | `storage` unusable (access throws, or a probe `setItem`/`removeItem` of `STORAGE_KEY + ":probe"` throws) → `state: "unavailable"` | US-001 rule 5 |
| 2 | `host` ∈ `TEST_HOSTS` and `search` has `RESET_PARAM` → `removeItem(STORAGE_KEY)`, `resetDone: true` (the UI removes the parameter with `history.replaceState`) | REQ-034, REQ-044, DEC-031, US-002 rule 9 |
| 3 | no key → build the seed for `now` (demo-data.md), write, `seeded: true` | US-002, REQ-034 |
| 4 | key exists, JSON broken or `version ≠ 1` → `state: "unreadable"`, **no write** | DEC-031, REQ-043 |
| 5 | else sweep, write if changed, `state: "ready"` | US-009, US-014 |

On any other host `RESET_PARAM` is ignored (deployed build — DEC-031).

### 3.2 `readDay(date, now, { names })` → `{ ok, floors, desks }`

| Output | Rule | Source |
|---|---|---|
| `floors[]` | per floor `{ floor, booked, left = capacity − booked, full: left = 0 }` | REQ-009, REQ-010, REQ-024 |
| `desks[]` | per desk of both floors `{ desk, floor, taken, deadline \| null, checkedIn, name \| null }` | REQ-022, REQ-023 |
| `name` | only if `names = true` **and** the booking has `showName = true`; otherwise `null` | REQ-026, REQ-028, ASM-015 |
| `date` not bookable | `DATE_NOT_BOOKABLE` (past dates are never read — I-9) | ASM-010 |

### 3.3 `book({ date, desk, name, showName }, now)` → `{ ok, booking: { date, desk, deadline } }`

Checks in this order; the first failing one is returned.

| # | Check | Code | Source (AC) |
|---|---|---|---|
| 1 | store not ready | `STORAGE_OFF` / `STORAGE_UNREADABLE` | US-001 "Storage not available", "Saved data cannot be read" |
| 2 | `checkName(name)` | `NAME_REQUIRED`, `NAME_TOO_LONG` | US-016 all 4 scenarios |
| 3 | `isBookable(date, now)` | `DATE_NOT_BOOKABLE` | US-005 "Date outside the window refused at save" |
| 4 | `sameDayClosed(date, now)` | `SAME_DAY_CLOSED` | US-017 "Same-day booking at 23:59 is refused" |
| 5 | desk not in `FLOORS` | `UNKNOWN_DESK` | defensive (no AC) |
| 6 | floor full on `date` | `FLOOR_FULL` | US-006 "Full floor refuses", "Last desk taken in another tab" |
| 7 | desk taken on `date` | `DESK_TAKEN` | US-005 "Taken desk cannot be booked", "Two tabs — stale tab cannot double-book" |
| 8 | `nameKey` already booked on `date` | `NAME_ALREADY_BOOKED` | US-005 "Second booking under the same name…", "Same name with different case and spaces" |
| ok | add booking: `name = cleanName`, `nameKey`, `showName` (false when the switch is Off), `bookedAt = now`, `deadline = deadline(date, now)`, `checkedInAt = null` | — | US-005 "State effect of booking", US-017 deadlines |

### 3.4 `cancel({ date, desk, name }, now)` → `{ ok }`

| # | Check | Code | Source (AC) |
|---|---|---|---|
| 1 | store not ready | `STORAGE_OFF` / `STORAGE_UNREADABLE` | US-001 |
| 2 | no booking for (`date`, `desk`) after sweep | `NO_BOOKING` | US-007 "Booking already cancelled in another tab" |
| 3 | `nameKey(name)` ≠ booking `nameKey` | `NAME_MISMATCH` | US-007 "Wrong name" |
| ok | delete booking (also when checked in) | — | US-007 "State effect of cancel", "Cancel after check-in", "Name match ignores case…" |

### 3.5 `checkIn({ date, desk, name }, now)` → `{ ok, info? }`

Check-in reads the booking **before** the sweep, so a booking reaching its deadline gets `RELEASED`, not `NO_BOOKING` (I-7); the sweep then runs and is saved.

| # | Check | Code | Source (AC) |
|---|---|---|---|
| 1 | store not ready | `STORAGE_OFF` / `STORAGE_UNREADABLE` | US-001 |
| 2 | no booking for (`date`, `desk`) | `NO_BOOKING` | stale screen (I-5) |
| 3 | `date ≠ today` | `NOT_BOOKING_DAY` | US-008 "Check-in before the booking day is refused" |
| 4 | `nameKey(name)` ≠ booking `nameKey` | `NAME_MISMATCH` | US-008 "Wrong name" |
| 5 | already checked in | `ok: true, info: ALREADY_CHECKED_IN`, nothing changes | US-008 "Second check-in" |
| 6 | `now ≥ deadline` (strictly-before rule) | `RELEASED` | US-008 "Exactly at the deadline is too late", DEC-020 |
| ok | `checkedInAt = now` | — | US-008 "Check in before the deadline", "One minute before the deadline", "Name match ignores case…" |

### 3.6 `tomorrow(now)` → `{ ok, date, floors: [{ floor, booked, capacity, status }] }`

`date = nextWorkingDay(today)`; counts from the bookings after sweep; `status = floorStatus()`; **no names** in the result. Source: US-013, REQ-030, DEC-013.

### 3.7 `sweep(data, now)` (internal, exported for unit tests)

1. Release: delete every booking with `checkedInAt = null` and `now ≥ deadline` (compare `date + "T" + time` strings). — US-009, DEC-020
2. Retention (from US-014): for every booking with `date < today`: `pastCounts[date][floor] += 1`, delete the booking. — US-014, ASM-014, DEC-029

Returns `{ data, changed }`.

## 5. Two tabs open in the same browser

| Situation | Behaviour | Source |
|---|---|---|
| Tab 2 shows a desk free that tab 1 just booked | tab 2's `book()` re-reads → `DESK_TAKEN` (or `FLOOR_FULL` if it was the last desk); the UI re-renders tab 2 | US-005, US-006 two-tab scenarios |
| Tab 2 cancels a booking tab 1 already cancelled | `NO_BOOKING`; counts change once | US-007 two-tab scenario |
| Tab 2 without any action | updates at the next minute tick or when it becomes visible again (`visibilitychange`); no `storage` event listener | DEC-028, I-8 |
| Two writes in the same instant | not locked — accepted for a single-presenter demo | I-14 |

## 6. Storage unavailable or unreadable

| State | Reads | Writes | UI |
|---|---|---|---|
| Unavailable | `readDay` returns empty floors (0 booked) | `STORAGE_OFF` | message under the banner; Book / Cancel / Check in hidden (ui.md §3.6) |
| Unreadable | nothing read; data untouched | `STORAGE_UNREADABLE` | message under the banner; Book / Cancel / Check in hidden (ui.md §3.6) |

## 7. No network

`storage.js` and the whole app make **no** network request after the static files are loaded: no `fetch`, `XMLHttpRequest`, `WebSocket`, `sendBeacon`, analytics or web fonts. The seed is an ES module (`seed-data.js`), not fetched data (I-12). Checked by E2E (US-001 "No network calls with booking data").
